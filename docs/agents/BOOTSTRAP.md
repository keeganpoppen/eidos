# Bootstrap a fresh session

Open the repository at the desired revision and start at its root. The founding branch is `main`; do not assume a branch named `master`. Read the host's actual instructions and tool availability. This prompt is portable; it does not depend on a particular model ID or a hidden conversation memory.

## Copy-paste prompt

```text
Continue Eidos/Nema from NEMA-SEED-1. Read AGENTS.md and START_HERE.md, then the destination, V1, current-state audit, and workstreams they reference. Treat the repository as our durable shared context; do not rely on inaccessible prior chat.

Reconstruct the transformative target before changing code: a personal, authority-local reflective workbench around native Codex/app-server, where real work, context, evidence, views, delegation, alternatives, and improvement remain addressable. The calculus must sharpen that experience, not postpone it.

Inspect current HEAD, existing work, implementation, and tests. Distinguish current facts from the seed's aspirations. Choose the strongest next integrated V1 slice, with a justified recommendation rather than an unranked menu.

Use available high-effort reasoning and bounded parallel subagents: first independent read-only gap reviews, then disjoint implementation lanes under one shared contract, with independent authority/recovery and product-usefulness review. Follow docs/agents/ORCHESTRATION.md. Do not invent unavailable agents or permissions.

Proceed through implementation, integration, and verification—not just another plan—within the resources and authorization available. Prefer the real two-thread recovery/context/delegation loop over a disconnected new protocol demo. Preserve raw evidence, historical context, native Codex ownership, and the separation of Names, knowledge, and live authority.

Before ending or compacting, update the current handoff with exact changes, evidence, test status, uncertainties, and one runnable next action. Be bold about the destination, candid about what the code proves, and selective about what to build next.
```


## Expected first response and artifact

The new session should identify the actual checked-out revision, the intended loop, the biggest integration gap, and its chosen parallelization. It should create/update a task packet or handoff, not merely repeat this specification. If native Codex, subagents, or live data are unavailable, it should implement and validate the strongest offline/synthetic boundary it can while marking the real-native acceptance as unverified.

The seed phrase is only a retrieval/recognition cue. It grants no authority and is not a magic reconstruction of hidden model state.
