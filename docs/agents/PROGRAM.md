## Opportunity ordering and reversible decisions

1. **Established recorder prerequisite: bounded native capture (C6, V1-02/07/12).**
   The [integrated contract](BOUNDED_NATIVE_TRANSPORT_TASK.md) bounds native input
   before decode, retained events across wait_for/backlog, and display tails.
   Exact rejected bytes and a source-scoped capture cutoff preserve earlier
   completion without inventing success across a gap. Independent counterexamples
   caught EOF, parser, byte-boundary and recovery errors. Wire budgets do not imply
   process CPU/RSS, outbound traffic or total database quotas.
2. **Active integration frontier: an owned native lifecycle (C6).**
   The [opaque HTTPS experiment](../evidence/NATIVE_TLS_CONNECT_EXPERIMENT.md)
   establishes native proxy/custom-CA behavior against fixed local destinations.
   The [managed lifecycle experiment](../evidence/NATIVE_MANAGED_LIFECYCLE_EXPERIMENT.md)
   now observes near-expiry Plus→Free before readiness, and issuer denial after
   endogenous 401 recovery when issuer closure precedes thread creation. Its
   bounded stop leaves the native terminal unknown. Analytics must be explicitly
   disabled; mandatory Git attribution settings are native-added governance
   context. Static catalog, both OTEL exporters and ordered successful config
   loading exclude specific background writers, not every possible writer.
   Buffered successful token bytes remain outside tunnel closure's reach.

   Next require one successful managed synthetic turn and durable artifact/reopen
   recovery under the same controls. Couple that discriminator to one owned capsule
   per pinned investigation attempt: preserve C0 through login/reload/later edits,
   cancel only the owned process, never reconstruct authority after restart, and
   privately preserve raw login/account evidence. Reuse the existing worker/API;
   do not create a second agent loop. Fresh Ephemeral login per attempt is a
   provisional isolation choice with unmeasured usability cost. Production
   admission stays closed; no real account/model calls are part of this contract.

   The [derived catalog policy](../evidence/NATIVE_DERIVED_CATALOG_EXPERIMENT.md)
   remains an established prerequisite: Astra Lite declares empty tools and rejects
   resource/clock challenges with the labelled two-field patch. Preserve exact
   source/derivation and trust in the reviewed executable. This is not exhaustive
   hidden-handler proof. Ordinary Responses remains a simpler candidate if the
   eventual account supports it.
3. **Established product loop: return to a saved question (C1/C5).**
   The [recovery acceptance](../evidence/SAVED_QUESTION_RECOVERY_INTEGRATION.md)
   verifies discoverable entry, exact question/rationale/result preview and raw
   support before Open. Dirty/pending investigation drafts and working arrangements
   survive inspection. Current review is separately labelled; later results cannot
   fill a context-only alternative or replace a historical baseline. Baseline and
   changed UI were exercised against the same saved fixture. Scripted availability,
   exact recovery and navigation are established; human benefit remains unmeasured.

   **C2 scout outcome:** existing Discover/Await already supports two independent
   pending questions, out-of-order source decisions and local executor restart.
   The permanent regression preserves ordered incorporation, spent response
   authority and replay without new occurrences. Keep singular product admission:
   separate investigations and exact result inputs currently cover independent
   questions. The next experience discriminator is a returning owner using an
   explicitly supplied sanitized history to recover support and build a context;
   synthetic UI cases alone cannot establish usefulness or justify C4 activation.
4. **Established baseline: substantial saved work (C1/C5).** The 1,200-turn history
   and 1,000-owner HTTP/browser cases preserve stable source membership, bounded
   metadata pages, conditional reads, exact artifact detail and dirty draft/retry
   identities. Full first-owner reads, large individual turns and cold/dirty SQL
   indexing remain costs. Better lenses should be selected for demonstrated
   controlling-decision recovery, not merely smaller rendered payloads.
5. **Alternative: reversible recipe activation (C3/C4).** Choose this when observed
   repeated selection friction justifies a concrete recipe. Do not reward adopting
   a change whose only evaluation is smaller bytes or agreeable prose. Fixed
   one-inquiry process topology is another explicit C2 limit; challenge it with
   independent pending questions before adding more runtime vocabulary.

Trace storage and SQLite-derived indexes remain replaceable. Stable evidence,
context/attempt/artifact identity and the knowledge/authority distinction are more
expensive to change and deserve direct compatibility tests. Browser-local layouts,
fixed one-inquiry topology and current Python host adapters are implementations,
not mature-world axioms.

## Current integration boundary and next contract

The preceding opaque HTTPS/inquiry integration is `13abac7` (public CI passed);
the [handoff](CURRENT_HANDOFF.md) identifies managed-lifecycle verification
and the next positive-recovery / owned-capsule contract. See [D28/D29](../roadmap/DECISIONS.md) and linked evidence. The active
read index is a derived performance adapter, not a second provenance authority.
Native process/synthetic transport research is independent of production admission.

Historical paging contract: `GET /api/threads/:id` returns at most 40 complete turns.
`anchorSeq` follows a stable record; `aroundSeq` resolves exact membership in that
thread. Explicit next/previous anchors avoid guessing from interleaved ranges.
`knownVersion` can return an unchanged envelope; a SQLite read snapshot binds the
version to source state, semantic revision/reliability, selected map and page.
Actual `recordSeqs` establish item/turn membership. This bounds turn projection and
repeat transfer, not individual turn/outline byte size or all SQL index work.
