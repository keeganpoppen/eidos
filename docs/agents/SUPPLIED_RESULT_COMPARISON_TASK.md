## User-visible outcome

From an exact displayed result and one of its cited supplied result inputs, choose
**Compare with this supplied result**. Stage an ordinary arrangement with that
input's exact owner/context/artifact on the left and the displayed result's exact
owner/context/artifact on the right. Show the review before Apply; existing
Apply/Undo/Save/reopen semantics remain. Label the relationship as supplied input,
not agreement, causation, approval, a patch or execution.

The action must work for an authored finding without creating a native attempt or
rewriting its investigation editor. Use small typed callbacks/props and a pure
binding validator; no new serialized attention intent or backend protocol. The
displayed finding supplies its own context, never the currently edited context.
Expose the action beside the existing result citation/provenance affordance; avoid
dumping more IDs or technical machinery into the normal flow.

Resolve and validate exact originals before offering Apply. If the original owner,
context or result is unavailable or disagrees with the frozen input, report that
condition and retain the current arrangement/draft. The frozen copy stays readable
through existing provenance. Never substitute a newer result or manufacture an
owner from a frozen copy. Source review metadata may legitimately differ from the
historical selected review; that difference is not result-content corruption.

- Consumer R0 includes F0; source owner later gains F1/current C1. Staging must bind
  F0/C0 and R0's own context, including a historical R0 shown beside newer results.
- A current editable question, source selections/focus, unfinished finding and
  pending save identities remain byte-exact. Comparison staging is not a new draft.
- Read failure, source deletion, mismatched supplied content, close, a newer user
  request, manual binding edit, saved-comparison open and component disposal cannot
  let a delayed read replace a later arrangement or review proposal. Apply reuses
  the existing comparison change guard.
- Staging performs reads only. Apply changes browser arrangement only. Save writes
  only the existing composition route; restart opens the same exact pair. Undo
  restores the preceding arrangement/focus behavior.
- Existing recorded experiments, pending retry and saved synthetic examples remain
  available. Authored-only work stops advertising an irrelevant native inquiry.
- Check desktop and390px render, keyboard/button access, errors and cancellation.
  Helper tests should falsify identity/cancellation mistakes, not mirror labels.
