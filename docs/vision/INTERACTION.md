# Interaction: many apertures into one addressable world

**Status:** aspirational interaction contract. The existing UI is partial. Do not lose the experiential ambition while the calculus evolves.

## I1. More than a transcript with a sidebar

Make the relations between conversations, artifacts, processes, context, and decisions directly manipulable. A thread list and JSON inspector are scaffolding, not the destination. The person should work through several coherent views without manually transferring the same context among applications.

The browser client can establish this first. Terminal renderers, native windows, extensions, and sidecars can follow the same semantic contracts. The world should not cease to exist when its one control window closes.

## I2. Four presentation concepts

These are library conventions, not new kernel primitives.

**Surface:** an addressable substrate on which a participant presents or receives interaction: a browser window, terminal pane, tab, artifact view, agent context interface, or remote host surface.

**Lens:** an interpreter/rendering of selected world content, with source scope, version, and meaningful affordances. Chronology, argument, diff, dependencies, pending decisions, and evidence maps may be different lenses on the same work.

**Focus:** a referable selection/attention relation. An observer can focus a trace range, proposal, or process without imposing a single global selection on all participants.

**Aperture:** the scoped opening through which a lens sees and interacts: identity/query, time/cut, filters, semantic depth, context budget, and admitted actions. It need not equal an operating-system window. Several apertures can share a surface or an object.

A compositor is an opinionated interpreter of attention, not the one true layout engine. Interruption recovery, deep comparison, active execution, and compact terminal work may deserve different compositors. They share identities and interaction, not necessarily pixels.

## I3. Stable meaning through changing representation

Selecting a claim in an argument lens can reveal its exact source ranges in a transcript lens. An agent can request the actual patch rather than a prose description of it. Rearranging panels or changing renderers must not break object references.

Keep a binding's identity, its address in an arrangement, and its target distinct. Rebind a current-plan aperture without renaming the plan. Duplicate a view without duplicating authority. Share a scoped read projection without exposing every underlying private record. One world heartbeat means coordinated state, not a universal observer.

Useful compositional intentions may include present, present together, attend, retain, dismiss, inspect, and compare. These are candidate semantic actions, not frozen API names. An admitted compositor lowers requests into a concrete arrangement and records what actually happened.

## I4. Native meaning first

A patch deserves a diff. A pending answer deserves its question, alternatives, relevant context, and consequence. A process deserves useful output and an honest continuation state. A composition proposal deserves the arrangement requested and the arrangement realized. A branch comparison deserves comparable inputs and outcomes, not two completion timestamps.

Place provenance close to the claim it supports and allow expansion into raw evidence. Distinguish observation, inference, hypothesis, proposal, and committed action. Show whether an aperture is historical, live, simulated, stale, or incomplete.

The aesthetic is restrained, experimental, structurally candid, and high-bandwidth. Remove chrome, not meaning. Avoid generic dashboard cards, ornamental metrics, tiny text, repetitive labels, and navigation that hides substance. Brutalism is not an excuse for poor accessibility. Keyboard use, stable selection, clear typography, and large-conversation performance matter.

## I5. In-situ reflection

The user and agents should inspect and change the apparatus while using it. A view exposes its query, model/lens version, context aperture, and action bindings. A context builder shows selected evidence and why it was included. A specialist result exposes the context actually supplied, not only what the agent says it remembers.

Changes to lenses, arrangements, context bindings, and executable behavior have different consequences. They need reviewable operations and an undo path, not one ambiguous Apply button. Some changes are pure presentation; some affect future input; some alter live authority.

A request such as “compare this decision with the earlier experiment, keeping the evidence and resulting diff visible” should produce an inspectable composition proposal. The user can adjust its aperture or binding before adoption. Arrangement proposals and their outcomes become evidence for improving future presentation.

## I6. Prompts and UIs are distinct backends

A meaningful interaction can be lowered into a model context, CLI argument, terminal prompt, browser control, or native artifact. The common layer identifies subject, supporting evidence, state, possible continuations, and admission conditions. It is not a universal bag of widget schemas.

A pending disclosure question might be rendered as a human decision view or supplied to a model/policy executor. In both cases its identity, deferrals, evidence scope, and decision authority remain explicit. A renderer must not invent an action the participant cannot perform, or show only an approval-tool name while omitting its actual question.

Semantic continuity matters; pixel equality across platforms does not.

## I7. The first useful arrangement

In a saved workspace, support a semantic navigation lens over imported/live threads, an evidence aperture with exact and noncontiguous support, a work aperture for the current context packet/process/question/diff, and a way to compare an alternative beside the baseline.

These are not four permanent columns. The user may collapse, move, combine, or replace apertures. Reclaim space when an investigation ends while preserving the arrangement for recovery.

The first reflective action can be modest but complete: select evidence from two threads, preview a named context packet, delegate bounded work, show waiting/progress and its result artifact, then reintegrate selected conclusions with source links. It should feel like working on the project, not administering a framework.

## I8. External surfaces without replacing every tool

Long-term, browser tabs, existing applications, terminal multiplexers, editors, and windows can become addressable participants through adapters. An extension can refer to the current page without requiring all browsing inside Nema. A terminal process can surface a pending question into an existing aperture rather than an unrelated chat.

Do not assume every external application is controllable or every tab grants access to its contents. Discover and admit the actual host capabilities. Preserve useful semantics with the smallest adapter; do not require compulsory replacement of the user's tools.

## I9. Experience acceptance

Use real long conversations and large diffs, not only small fixtures. Reload must preserve arrangement, selection, and provenance. Unrelated updates must not steal focus or scroll position. Pending work must show who can answer and what remains unknown. Comparisons retain their baseline. Keyboard navigation and links work across disjoint evidence ranges. Unsupported native actions are labelled, not simulated as success.

Have someone perform the recovery/delegation task in the actual UI. A successful build is not evidence of a successful interface. Keep sanitized screenshots or interaction recordings as review artifacts.
